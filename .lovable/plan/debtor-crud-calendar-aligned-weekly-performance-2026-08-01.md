# Debtor CRUD + Calendar-Aligned Weekly Performance

## 1. Debtors CRUD (highest priority)

### Where
A new **Debtors** tab inside Database Management (next to Inventory / Sales Transactions / Debt Records / Product Management), admin-only. The existing Debtors list in Admin and Accountant dashboards keeps showing the same data, now including manual entries.

### What an admin can do
- **Create** a manual debt entry ("opening balance debt"): customer name (picked from the customer list, or a new name), shop, amount owed, date issued, due date, optional note.
- **Read** all debt entries for the selected shop in a compact table: customer, shop, issued date, due date, billed, paid, balance, age, status (Good / Long / Bad), source (Manual vs Sale).
- **Update** any field of a manual entry: customer, shop, amount, dates, note. Manual entries created here can be edited; entries generated by real credit sales stay editable through the existing Sales Transactions tab (so totals stay consistent with their line items).
- **Delete** a manual entry, with a confirm step. Deleting is admin-only.

Amounts already paid against a manual debt come from the existing debt-payments flow, so a manual debtor can be paid down and receipted exactly like a credit sale.

### Consistency
- Manual entries roll into the same aging buckets, KPI cards, outstanding-debt totals and debtor counts everywhere (Admin overview, Accountant reports, Executive dashboard) — no separate numbers.
- Customer names are normalised the same way as sales, so a manual debt for "james" merges with sales for "James".

## 2. Weekly performance aligned to calendar weeks

In the Accountant Reports weekly grid, weeks become fixed month chunks:

```text
Week 1: 1st  - 7th
Week 2: 8th  - 14th
Week 3: 15th - 21st
Week 4: 22nd - 28th
Week 5: 29th - end of month (28/29/30/31)
```

- The grid shows exactly the days in the chunk (the last chunk can be 1-3 days, not padded into the next month).
- Prev / Next step chunk-to-chunk and roll over into the previous/next month's chunk correctly.
- Header shows "Week 3 (15-21 Aug)" style labelling, and "This week" jumps to today's chunk.
- Totals column still sums only the days shown.

## Technical notes

- **Database:** manual debts are stored as rows in `sales_transactions` with `is_credit = true`, `total_amount` = amount owed, `amount_paid` = 0, `due_date` set, and a marker (`sale_type = 'opening_balance'`) plus no `sales_items`. This makes every existing debt query, aging bucket, receipt and debt-payment allocation work unchanged, with zero schema migration.
- Writes go through the existing admin edge-function/session path used by the other Database Management tabs, so RLS/auth posture is unchanged.
- New file `src/components/admin/DebtorsManager.tsx` for the CRUD table + create/edit dialog; wired as a tab in `src/components/AdminTableEditor.tsx`.
- `src/components/accountant/AccountantReports.tsx`: replace the fixed 7-day `weekDays` builder with a month-chunk range helper (start/end + clamped length) and chunk-based prev/next navigation; `WeeklyGrid` already renders a variable-length `days` array, so it needs no change.
- Debt entries with `sale_type = 'opening_balance'` are labelled "Manual" in the debtors list and excluded from bags/product sales analytics (they have no items, so this is already true).
